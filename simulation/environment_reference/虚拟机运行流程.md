# 在虚拟机里怎样运行这个项目

项目目录是 `/home/haosheng/hs_ardupilot_stage1`。VS Code 用来阅读和编辑源文件，Ubuntu 终端负责执行下面的命令，Gazebo 窗口显示实际仿真运动。

## 1. 进入项目目录

```bash
cd ~/hs_ardupilot_stage1
```

## 2. 启动场景与虚拟飞控

如果已经有场景在运行，先结束它，再从地面初始状态启动：

```bash
bash scripts/stop_scene.sh
bash scripts/start_scene.sh
```

`start_scene.sh` 生成车机共同场景，启动 Gazebo，等待时钟和 IMU 初始化，然后通过 `run_fcu.sh` 启动 ArduCopter SITL。此时无人机还没有执行起飞任务。

## 3. 运行自己的姿态 PID

```bash
bash scripts/run_attitude.sh --task follow --car-speed 0.25 --drive-seconds 10
```

该脚本实际运行 `tools/attitude_demo.py`。它调用 `control/attitude_pid.py` 中的姿态角 PID 和速度 PI，调用第一阶段 `first_stage/core.py` 中的协同位置控制。启动脚本设置了所需的环境路径，因此不需要额外手工切换 Python 环境。

## 4. 看运行日志和 Gazebo 动作

```bash
tail -f results/attitude_demo.log
```

日志中的阶段：

| 阶段 | 对应动作 |
|---|---|
| READY | 获取模型和飞控反馈，等待初始化 |
| ARM | 正常解锁电机 |
| TAKEOFF | 自己的控制链给出推力与角速度指令，让无人机上升 |
| HOVER | 悬停 |
| YAW_DEMO / YAW_RETURN | 朝向增加 20°，随后回到原朝向 |
| ALIGN | 飞到车辆平台上方并对准 |
| FOLLOW | 车辆行驶，无人机跟随 |
| STOP_VEHICLE | 车辆停车 |
| LAND_DECK | 下降到车顶，等待实际接触 |
| LAND_CONFIRM | 接触后由飞控完成正常停转 |
| COMPLETE | 整个任务完成 |

用 Ubuntu 的 Alt+Tab 可以切换 VS Code、终端和 Gazebo。

## 5. 看结果与停止

`results/attitude_demo.csv` 保存飞行数据，`results/attitude_demo_status.json` 保存完成结论。终端按 Ctrl+C 结束日志查看；停止整个仿真需要另外运行：

```bash
bash scripts/stop_scene.sh
```

## 本次现场展示入口

```bash
bash scripts/show_flow.sh
```

这个展示脚本按顺序执行上述实际命令，并把命令和真实输出留在 Ubuntu 终端。首次运行时，将前一次姿态演示的数据另存到 `results/pid_first_run/`。查看控制原理时，在 VS Code 中打开 `control/attitude_pid.py`；查看动作顺序时打开 `tools/attitude_demo.py`。

需要在启动场景与运行控制器之间停留、边看边讲解时，可以运行：

```bash
bash scripts/lesson_flow.sh
```

这个讲解脚本先归档上次的数据，再启动真实场景，停留 30 秒供观察地面模型，然后实际运行姿态 PID 任务并显示日志。它是流程展示入口，控制算法仍然位于 `control/attitude_pid.py` 和 `tools/attitude_demo.py`。
