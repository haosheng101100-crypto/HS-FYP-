# 第七阶段：无人机择机降落决策算法

## 1. 本阶段要解决什么

根据车辆平台未来运动的预测，以及无人机自身的位置、速度、高度和运动能力，主动比较“现在下降还是稍后下降更合适”，选择开始末段下降的时间和接触平台的时间。

车辆减速、转弯等是寻找着陆机会的运动线索，不直接写成“减速或转弯就下降”的固定规则。是否值得落，要由可执行轨迹、预测不确定性、接触余量和等待代价共同决定。

目标是在声明的运动范围内抓住可达的着陆机会，完成真实接触、正常停转和持续支撑；暂时没有机会时跟随或准备，条件恶化时恢复，任务无法继续时退出。有机会却一直等待或总是退出，同样属于功能未完成。

## 3. 核心方法：外层选时间，内层算轨迹

设当前时刻为t0：

- w：开始末段接触下降前的跟随／准备时间。
- T：末段下降用时。
- 开始下降时刻：ts = t0 + w。
- 接触时刻：tc = t0 + w + T。

外层采用粗到细的有限候选搜索，比较不同(w, T)；内层复用第五阶段的Bézier优化器求轨迹。

每个候选必须包含连续的“跟随／准备段 + 末段下降”，并从实际状态和最后发送参考接续。不能假定等到未来ts时无人机已经自动对齐，也不能把当前状态直接复制为未来起点。

## 4. 每一轮的算法流程

1. **读取与对齐输入。** 接收无人机实测状态、最后下发参考、实际脚底净空、接触事件、任务预算，以及第六阶段最新平台预测；统一物理时钟、坐标和绝对目标时刻。
2. **生成候选机会。** 枚举等待时间w和末段用时T，先做廉价可达性筛选，再对较有希望的候选调用第五阶段求解。
3. **检查是否能落。** 对同一条无人机轨迹，检查所有保留的平台样本及工程误差余量下的整机落区、相对速度、姿态、飞行限制和接触前碰撞，覆盖触地时间窗口。
4. **检查是否能恢复。** 检查执行当前短前缀、再经历声明响应延迟后，备用制动和恢复动作仍可执行；包含下沉速度、加速度、jerk、水平漂移和未来甲板扫掠。
5. **比较合格候选。** 排除不合格轨迹，再比较完成时间、预测分散、接触余量、轨迹控制负担和改期代价。
6. **执行最优候选的一小段。** w接近零且最新检查合格时启动末段；w大于零时先执行对应的跟随／准备参考。
7. **用新观测滚动更新。** 继续检查机会是否成立，必要时改期、恢复或退出；实际接触后进入原LAND、停转与支撑检查。

“最优”指当前信息、模型、已审核候选和计算预算下的最佳选择，不是预知真实未来的全局最优。

## 5. 合格候选怎样评分

建议初版使用无量纲代价：

```text
J = λt (w + T) / tref
  + λu U
  + λm / (ε + M)
  + λe E
  + λs ((tc - tprev) / tref)^2
```

- U：接触窗口内平台位置、速度、航向预测的最大归一化分散度。
- M：所有样本下最小的归一化接触余量；原安全门限必须先满足。
- E：复用第五阶段jerk／snap等轨迹代价，包含跟随／准备段；是平顺与控制负担代理，不直接等于真实电能。
- tprev：上一轮选定的绝对接触时刻，首次选择不使用改期项。
- 权重、归一化尺度和ε在开发阶段固定，通过已知可行窗口与飞行响应调整，验收时保持一致。

该评分是本项目的工程方案，不是下列某篇论文的原公式。安全约束不能由其他项目的低分抵消；当前IMM权重也不能直接当未来着陆成功概率。

## 6. 两段下降与短期预测的衔接

**准备接近：** 从高处向合适的准备位置移动，减小相对状态误差，同时保持可恢复能力。第五阶段增加STAGING目标：终点在平台上方、相对竖直速度为零，不授权接触。

**末段接触：** 当等待、末段下降、触地时间窗口及必要执行延迟都落在当前有效预测时域内，才使用原TOUCHDOWN目标授权接触下降。

第六阶段目前约两秒的样本预测，不能解释为“等待一秒后，还能额外使用原来的两秒”。较长条件名义轨迹用于准备引导，不能当成同样长度的可信范围。准备高度根据恢复距离和末段所需时间求可行范围，不先固定成任意高度。

## 7. 在线执行必须保留的要求

- 用同一条当前执行轨迹检查多种平台未来，不能让已执行动作依赖尚未观测到的未来分支。
- 每个候选绑定自己的恢复检查、接续参考、生效时刻和验证预测编号，不能混用其他候选的备用动作。
- 轻量监督持续运行，重型轨迹求解放后台。实际频率以本机测得的计算和响应时延确定。
- 新预测编号出现不直接使异步结果作废；结果生效前，用最新有效预测重新审核其前缀、接触窗口和绑定备用动作。
- 保留原观测新鲜度门限、指令限制、物理接触优先及接触验收。第七阶段启用后统一选择任务动作，避免旧、新阶段机同时下令。
- 当前机会仍可用时，新机会须有足够收益才改期；安全失效立即响应。等待、改期和重试均受任务预算限制。
- 无合格接触候选但仍有安全准备动作时继续准备；观测失效或预算用尽时执行已检查的退出路径。
- 有限样本包络加工程余量不等于正式概率保证或确定性全覆盖。不得缩小安全余量或删除困难分支来制造着陆窗口。

## 8. 实施顺序与阶段交付

| 步骤 | 工作 | 完成标志 |
|---|---|---|
| 1. 接续接口 | 冻结基底，接入预测、无人机实际状态、时间和编号 | 输入能对齐并可因果回放，旧功能基准保留 |
| 2. 机会比较 | 生成(w,T)，检查接触窗口，计算各项代价 | 能区分立即下降与主动等待，并解释原因 |
| 3. 恢复能力 | 实现短前缀后的制动、净空和备用动作检查 | 下降前能判断是否仍有退路 |
| 4. 规划目标 | 在第五阶段同一优化器中接入STAGING与TOUCHDOWN | 准备段和末段连续，准备到达不误触发LAND |
| 5. 完整监督 | 接入原生operator、异步结果重验与动作切换 | 跟随、准备、下降、恢复、重试和退出连贯运行 |
| 6. 物理验收 | 回归已有三条链，再验证新择机行为与边界 | 同一版本真实落台／正确退出，视频与证据可核对 |

新增验收必须包括：现在已可落但稍后更好、未来窗口即将消失应立即行动、准备下降中变化后恢复再落、全程无窗口有界退出、观测中断和求解迟到。先每类一次覆盖功能，关键链路少量复测；不恢复旧92场计划。

Linux负责具体推导、实现、测试和Gazebo／ArduCopter仿真；Windows负责方案与结果复核，GitHub同步版本和必要证据。源码、运行说明、配置和结果分别标明版本；不得将不同版本结果混为同一成功率。

### 按实际工况设置决策窗口与事后评价时长

由Linux实施端根据平台运动周期、无人机初始相对状态、预测预热、准备／下降／恢复用时及后验比较需要，设置每类工况的决策窗口和仿真总时长。**不采用统一固定秒数，不默认沿用口头举例的5秒或10秒。**

验收流程是：

1. 在适合该工况的前段时间内作出明确决策，保存动作、计划开始下降与接触时刻、当时预测、候选及评分。
2. 仿真在决策后继续运行足够长，观察车辆实际运动、无人机执行、触地支撑或恢复退出，也保留可比较的其他着陆机会。
3. 运行结束后分别评价：是否在规定窗口内作出决策、执行是否合格，以及相对其他可行时机的选择质量。

开发试跑可根据实际耗时修改配置并说明原因；正式比较前记录时间起点、窗口长度、总时长及设置依据。如需按事件动态延长，应预先定义触发条件和最大时限，不能看完结果后改时限来掩盖失败。使用活动物理时钟，并记录暂停及仿真倍率。

首次选择、截止时刻的选择和后续安全重规划分别保存。决策截止不等于必须已经落台；若结束时动作仍未完成，应按预定规则延长或标记未完成／证据不足。

后续真实运动只用于相应的事后评价，不能提前输入在线预测或决策。比较其他时机时，应在相同初态、车辆运动和约束下离线重算，必要时分支重跑；不能直接套用原无人机轨迹。后验全知基准用于衡量机会损失，不等于要求在线算法预知未来；有限候选中的最佳不称连续全局最优。

## 9. 流程伪代码

```text
读取实际状态和接触事件
若已接触：进入原LAND、停转和支撑检查

读取第六阶段最新有效预测
生成候选等待时间w与末段用时T

对每个候选：
    调用第五阶段连续规划跟随／准备段和末段
    审核同一轨迹在平台多种预测下的接触条件
    计算并绑定该候选的恢复检查与备用动作
    不合格则排除；合格则计算机会代价

选择已完整审核候选中代价最小的一条
用最新预测重验后：
    若w接近零，执行末段短前缀
    否则执行跟随／准备短前缀

无合格候选时：
    有可执行准备动作则继续准备
    否则恢复或退出

接收新观测，重复判断
```
