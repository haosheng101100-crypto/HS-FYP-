# M17中段换向覆盖不足：原始数据诊断（2026-11-04）

本轮没有新增物理飞行，没有修改控制算法、轨迹、profile、原审计或安全门限。原M17仍为coverage_failure，安全/物理审计通过，不能改称完整工况通过或落台。M07结果已单独发布在ab9426d7b5eede94f798aaa1d52d343a370ccab9。

## 查明的现象和机制

对原20工况M17和6e9b2c7慢速末段版本M17逐字节核验完整原始位姿，分别重算实际平台速度。两次均在换向触发后0.76s由原监督器安全退出；平台真正反向并满足原速度/方向条件及连续三原始区间的证据，分别在触发后2.737s与2.713s才出现，即退出后约1.98s与1.95s。平台换向执行正常，下降期间完整反向覆盖没有实现；退出后运动不用于补算下降覆盖。

新版触发脚底净空约2.083m、下降速度约0.693m/s，退出时净空约1.561m。原因是预测捕获窗口失效后，实际/已发送参考所需制动距离加原最低重跟随净空及余量，超出当时可用净空，进入PLANAR_CHANGE_WITHOUT_REACQUISITION_CLEARANCE。不是平台收到指令就瞬间反向，也不是等待平台反向后才执行安全退出。

平台原命令限制为加速度0.12m/s²、加加速度0.3m/s³，从约+0.25m/s变为反向需时间。只考虑理想标量命令加速度界，达到-0.04m/s也至少约2.42s，尚未计入加加速度和伺服响应；这仅解释命令时间尺度，不是含任意物理扰动的实际安全证明。同一PlanarMotionCommand的独立确定性回放约2.62s达到该反向速度条件，与原始物理数据方向一致。

## 处理决定

保留原失败结论和全部既有数据。本轮不重复同样条件的物理飞行，不延迟退出、不提高平台加速度、不提前原2m触发，也不放松原覆盖检查。当前已验证的是此条件下能正确安全退出，尚未验证2m换向后完成反向并继续落台；原要求本身允许安全退出，不强求落台，但原严格覆盖不足仍记录。

若以后明确要求低空换向后仍继续完成任务，应另行设计中段下降/恢复轨迹并审查可用净空，随后保留旧场景做针对性回归；不能仅把触发提高后命名为原M17通过。按用户当前功能演示范围，不扩展为新大批次。
