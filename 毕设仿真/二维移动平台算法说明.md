## 算法链路

1. 位置观测进入原 CA Kalman 滤波器。新配置按观测创新临时增大 XY 过程噪声；不使用平台命令或未来轨迹。
2. `MotionChangeMonitor` 比较已到期的短期预测与实际观测，检测速度/位置预测变化、加速度变化和跨零反向。低速方向不用于反向判定。变化后需重新稳定至少 0.8 秒。
3. 尚未下降时，用现有 jerk 有界参考在脚底安全高度 1.5 米附近跟随。必须同时满足原对齐/入口检查、运动稳定和局部接触窗口，才启动下降规划。
4. `capture_window` 检查预测接触前后各 0.2 秒的加速度及其造成的速度变化；局部接触加速度限值 0.11 m/s²，低于原 1° 水平着陆姿态所对应的静态水平加速度能力。1.2 秒之外的长进场仅为待在线复核的条件候选，不授权接触。
5. 规划器保留原目标函数、终端零加速度/jerk、原速度/加速度/姿态/整机约束。额外采样最后 0.16 秒各脚底的切向相对速度，超过原 0.05 m/s 接触速度限值则拒绝候选。该附加采样不是连续碰撞证明。评分下界裁剪依然只裁剪严格被支配候选，不改评分。
6. 下降中丢失窗口，必须保留 1.25 米跟随净空底线，再加实际跟随参考的停止下降距离和 0.25 米余量，才允许重新跟随。停止距离按实际可用竖直加速度 0.4 m/s²、竖直 jerk 1.2 m/s³计算，并取实测运动与已发送参考运动中更保守的结果，补偿两者的高度差。跟随参考独立预留竖直制动能力，避免横向纠偏占用它。取消旧后台请求，保留递增请求序号，从实际已发送 P/V/A 初始化新参考。最多重新跟随 3 次，总等待最多 25 秒，总任务最多 40 秒；这些预算不随重新规划重置。
7. 净空不够、观测过期或预算耗尽则沿原制动/升高/返航流程退出。真实接触和已经开始的原生 LAND 始终优先，不会被重新跟随覆盖。原 1 厘米接触窗口、整机边界、正常停转、停转后支撑检查保持。

变化期间会在原经验预测误差半径上增加已观测创新的传播余量，不增加虚构样本数，也不宣称概率覆盖或未知未来运动保证。

## 新仿真平台

旧模型是差速轮式车辆，不能在不转向时横移。因此本版独立生成两轴移动导轨，使用 Gazebo Harmonic `JointController` 的 `use_force_commands=true` 模式施加有界关节力；不写入平台位姿、不直接设置机体速度。原 chassis、甲板碰撞、摩擦、传感器及无人机资源保持字节不变，运动机构单独声明，不能把它称为原轮式车辆。

官方接口依据：[Gazebo 8 JointController](https://gazebosim.org/api/sim/8/classgz_1_1sim_1_1systems_1_1JointController.html)。关节 PID 参数属于待物理验证的仿真设计值。

配置 `config/experiments/planar_landing_v1.json` 提供前后、左右、斜向、换向和二维连续变速场景。指令按 XY 合成速度/加速度/jerk 限幅。实际平台运动仍必须从高频物理位姿独立审计，指令满足限制不代表实际响应已通过。

## Ubuntu 后续运行

保留原环境、旧数据和原源码，在新的源码目录运行：

```bash
python3 tools/run_planar_simulation.py \
  --base /home/haosheng/hs_ardupilot_stage1 \
  --session /home/haosheng/hs_ardupilot_stage1/interactive_20261023/planar_session_001
```

必须选择不存在的新 session；原固定云台源目录或 moving_rapid 源包位置不同，使用 `--source` 和 `--frozen` 指定。启动器沿用原面板/飞控环境，属于独立仿真，不适用于真机。默认配置逐场运行新场景；执行前先检查没有其他运行中的 Gazebo/飞控占用相同端口。

每场应检查：

```bash
python3 tools/audit_planar_policy.py RUN
python3 tools/audit_guided_motion.py RUN
python3 tools/audit_native_landing.py RUN
# 按实际结果选择原接触或退出审计，退出不能算落台成功。
python3 tools/audit_receding_physics.py RUN
```

新策略回放审计覆盖多次跟随阶段和经验余量；历史 `audit_prediction_uncertainty.py` 仅支持单次对齐，不能直接用其旧结构审计多次重新跟随。原物理接触、正常 LAND 和原始 COM 运动审计仍须通过。策略回放通过本身不代表物理着陆成功。

物理验收还需确认：两轴指令确实带来两个方向的实际移动；原模型和甲板尺寸；换向后平滑重接；可着陆场景真正落台；不能着陆时提前退出；停转后平台继续运动不会造成滑移越界。当前没有任意运动或长期防滑保证。
