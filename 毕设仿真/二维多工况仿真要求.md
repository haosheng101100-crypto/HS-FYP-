## 1. 执行顺序与实现边界

1. 阅读LINUX接续工作说明.md、二维移动平台算法说明.md、重新跟随专项仿真说明.md及本文件。
2. 保留当前控制算法，先增加独立场景、配置和适配的审计。已有单次反向专项审计要求固定触发数量，不适合直接验证圆形运动或多次转向。
3. 生成并冻结20个唯一case的机器可读矩阵，再启动物理仿真。矩阵至少含case_id、类别、运动公式/命令序列、幅值、初相位、触发条件、初态、预期结局、覆盖条件、种子、超时和审计版本。
4. 先跑平滑持续运动，再跑启停/变向，最后跑下降阶段突变和不规则运动。每个case一次有效运行；环境中断可单独补跑，原中断保留。算法失败不能删除后换一次成功来顶替。
5. 新支持完整实现并验证后集中提交，再用冻结代码运行，结果提交引用实际运行commit。修算法后使用新版本/新批次，只重验受影响工况及必要回归，不自动启动重复性计划。
6. 不在Windows端另改控制代码；不操作论文仿真。新电脑先核实完整依赖、固定固件和模型，GitHub包不含本机容器镜像/所有运行依赖，不宣称任意Ubuntu直接一键跑。

以下参数是场景设计目标。Linux端须将未指定的精确持续时间、曲线尺度/初相位、触发容差和种子在矩阵中补齐并冻结；先检查动力学可实现性与场地范围。设计无法实现时记录原因，在运行前修订声明，不能运行失败后悄悄换工况。

## 2. 首轮20种工况：各一次

所有速度是平台二维合成速度；触发使用实测状态和真实阶段，不使用预计下降时间冒充实际下降。

| ID | 工况 | 设计目标及必须覆盖的行为 |
|---|---|---|
| M01 | 非轴向匀速30° | 0.25m/s，非X/Y/45°方向进场并落台 |
| M02 | 非轴向匀速135° | 0.45m/s，另一象限进场并落台 |
| M03 | 持续顺时针圆周平移 | 半径2.5m，稳态速度0.25m/s；接触前持续转弯 |
| M04 | 持续逆时针圆周平移 | 半径3m，稳态速度0.45m/s；与M03不同方向和曲率条件 |
| M05 | 椭圆平移 | 两半轴3m/1.5m，连续参数化，合成速度峰值目标0.30m/s；检查沿程曲率变化 |
| M06 | S形平移 | 一轴持续推进、另一轴平滑往复，至少经历一次曲率变号后接触 |
| M07 | 8字平移 | 连续光滑Lissajous或等效8字，实际跨越交叉区域且运动方向持续变化 |
| M08 | 斜向平滑加速 | 在非轴向从0.10升至0.45m/s，后段保留足够稳定运动时间 |
| M09 | 两轴不同步变速 | vx与vy分别变化，合成方向和速度同时变化，峰值目标0.45m/s |
| M10 | 移动后减速停住 | 0.30m/s平移后平滑停止，识别停止后的着陆窗口 |
| M11 | 停止后再次启动 | 停留后重新启动到另一斜向，必须在接触前观测到再启动；随后保持可落窗口 |
| M12 | 圆滑90°转向 | 平台平移速度方向转90°，甲板朝向不变；物理速度连续 |
| M13 | 圆滑135°转向 | 更大方向变化，之后保持稳定斜向运动供着陆 |
| M14 | 先X后Y两次方向变化 | 至少两个实际方向变化，若有重新跟随，逐次核对恢复链路 |
| M15 | 两次180°反向 | 下降中首次反向；真实重新对齐和新计划激活后再触发第二次，不能超原预算 |
| M16 | 下降早期换向 | 实测脚底净空约3.6m触发，初始跟随净空4m，目标变化必须经过原整形 |
| M17 | 下降中段换向 | 实测脚底净空约2.0m触发，与M16比较恢复/退出决策，不强求落台 |
| M18 | 临近接触改变运动 | 实测脚底净空约0.20m触发方向变化；检验可继续、恢复或安全退出，禁止强行制动上升覆盖已开始LAND/真实接触 |
| M19 | 有界不规则二维运动 | 固定种子，在不同斜向目标间按预声明间隔切换，经原速度/加速度/jerk整形；随后保留明确稳定尾段 |
| M20 | 持续有界变化直到原超时 | 与M19不同的固定种子/切换规则，无刻意添加稳定尾段；检验真实存在窗口则落台，否则有界等待/恢复并正确退出 |

M01—M13为“争取完成着陆”的可落性目标组。M14—M20为恢复与边界探索组，实际是否存在窗口需用数据解释。
这不是允许把前13种全部安全退出仍称功能完成：若退出，记录为未达落台目标并定位原因。反过来，后7种也不能把任何退出都直接判正确，必须通过原安全退出审计。
M14/M15需要多次事件覆盖；原重试最多3次、累计等待25s、总任务40s保持。未覆盖到第二次动作应列为覆盖失败；不能暗中增加时间或高度来取得成功。
M18的事件命令与实际平台加速度/速度变化有响应延迟。若物理变化仅在接触后才发生，就没有覆盖“接触前突变”，应列覆盖不足；保留结果，不强行放大平台响应。必要时另声明较早触发的追加case。

## 3. 让工况确实不同、确实符合物理模型

- 新圆形/椭圆/S形/8字工况在下降和接触前保留连续曲线运动，不能通过提前改成直线或停车把“曲线着陆”做成直线着陆。若算法只能等待它变直/停下，明确记录能力限制。
- 几何曲线参考只能交给场景平台控制器，不能直接写物理位置/速度。保留现有二维关节有界力控制及真实状态发布；初始摆放只在每场启动前完成。
- 保持原合成命令整形：速度上限0.8m/s、加速度0.12m/s²、jerk0.3m/s³；曲线启动/结束也要平滑，不能瞬间切换到圆周速度。
- 圆周稳态向心加速度为v²/r，椭圆/S形/8字需逐点检查峰值。若整形使实际路径偏离目标，不算错误隐瞒：同时画目标和实际路径，说明实际覆盖到的速度、曲率与转向行为。
- 初始飞机/平台位置和首次允许下降时的真实脚底高度逐场记录。优先使用4m专项初态并保持组间可比；若为新任务另选高度，先声明，不能把初态改变称算法性能提升。
- 场景端可以读取真实状态来触发扰动，但控制/估计端只能用当前及历史观测。禁止传入未来曲线、随机序列、换向时间表或目标命令来辅助预测。
- 本轮不叠加额外噪声/延迟压力矩阵；记录实际观测链路及年龄，避免把旧配置里的未启用噪声字段当作已注入噪声。

## 4. 保持原算法与限制，暴露问题后再改

保留预测→窗口判断→有限候选轨迹优化/选择→在线重规划→接触检查的结构。
不是发现任何变化都上升：小变化仍满足条件时允许继续重规划下降；失去窗口且可安全制止下降时恢复跟随，需要时上升；恢复空间不足或预算耗尽时退出。
对持续转弯，稳定是“短时可预测且相对接触状态满足要求”，不是强制要求平台速度方向永久不变。若现有变化检测把所有曲线运动永久挡在下降之外，保留证据，定位窗口/预测/监督问题，再提出修改。

不得扩大甲板、缩小机体或放宽保护换取通过：
- 原整机/旋翼扫掠包络面积与甲板面积1.5倍关系、接触几何和真实支撑模型保持。
- 原引导段实际COM速度3m/s、加速度1.5m/s²、发送jerk4m/s³保持；原名义规划/反馈余量和竖直制动能力保持。
- 接触水平姿态1°、切向相对速度0.05m/s、法向闭合速度0.02—0.12m/s、整机边界余量0.02m、原接触时间与LAND门限保持，正常非强制停转后检查3秒支撑。
- 总任务40s、累计等待25s、最多3次重新跟随不能重置或增加。
- 明确原生起飞、引导飞行、冲击、原生LAND的统计范围；平台命令加速度限幅不是实际物理加速度硬保证。

## 5. 验收不是看一段视频

每场需有原始物理轨迹、控制记录、真实场景覆盖及以下原审计：飞机COM运动、接触/整机几何、原生LAND和非强制停转、停转支撑、平台实际运动、因果策略和规划请求历史。
持续曲线另查实际两轴运动、曲率/方向持续变化和接触时平台是否还在曲线上。多次变向另查每次事件顺序、真实重新跟随、再次对齐、新规划激活和预算。
不要求每场都发生重新跟随；连续重规划直接完成曲线着陆也可正确，但必须说明实际路径。

先补审计的场景适配和相应测试，保持原检查门限。不能用原工具“不认识场景名”当算法失败，也不能为了适配把所有未知事件直接判通过。
对每场给出一个明确结局：
1. 真正落台且全部要求通过；
2. 正确安全退出，保护原因和退出过程均可复核；
3. 覆盖失败（例如第二次变化未发生、轨迹只走直线、扰动发生太晚）；
4. 算法/控制/物理失败或审计失败；
5. 环境中断/证据不足。
分别说明“是否达到该场落台目标”与“安全性是否合规”，不混成一个成功率，也不宣称20场等于任何二维运动都验证完。
