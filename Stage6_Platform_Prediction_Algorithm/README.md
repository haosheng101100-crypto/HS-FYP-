## 研究思路

### 车辆运动模型

预测先要符合车辆的运动方式。位置变化与车速、车身航向、转弯程度应当一致，同时受到加速度、转弯能力和变化速度的限制。

第一版考虑低侧滑条件下的平面运动。可用曲率描述转弯，初步模型为：

```text
dx/dt   = v cos(psi)
dy/dt   = v sin(psi)
dpsi/dt = v kappa
dv/dt   = a
da/dt   = j
dkappa/dt = eta
```

其中，psi 为航向，kappa 为曲率，a 为纵向加速度，j 和 eta 分别描述加速度、曲率的变化率。除各自上限外，还要考虑转弯横向加速度 v²|kappa| 与车速的关系。具体状态选取、离散形式、约束和参数由实现端推导后记录。

模型中的位置应对应明确的车辆参考点。若观测来自甲板中心，需处理参考点与甲板之间的偏移。低速、停车时不能直接用“航向角速度除以车速”估计曲率；此时转弯状态可能无法从观测中辨识，应保留不确定性。

这个选择参考了 Trajectron++ 对外部车辆参数难以获取的讨论，以及随机运动学模型对车辆轨迹生成的处理[3—5]。曲率模型是本项目的初步选择，并非直接复现某篇论文。

### 当前状态估计

输入以带时间戳的位置、航向观测为基础。有明确来源的速度、IMU和观测质量信息可以使用；轴距、前轮转角、未来控制命令和预设路线不能默认已知。

先比较 UKF 等非线性滤波方法，估计当前速度、加速度、转弯状态及其不确定性。实现中要处理航向环绕、时间对齐、观测缺失和过期。滤波器的选择以误差和计算耗时为依据，相关方法分类见综述[1—2]。

### 多种可能的未来

单一外推很难表达尚未确定的运动变化。第一版保留几种通用运动模型，例如近似匀速、速度变化、近恒曲率和曲率变化，并根据新观测更新各模型的权重。

这些模型对应运动机制，不代表预先知道车辆将做哪种动作。可比较 IMM 式模型更新与其他轻量多假设方法；具体实现需要给出方程和依据。MTR、Trajectron++ 等工作说明了保留多种未来的价值，但本阶段不直接套用完整的大型网络[1—2、4、6]。

不同分支应分别保存。两个转向分支不能简单平均成一条直行路线；未来输入的变化也应保持时间连续性。分支数量和筛选规则固定后，再进行后续校准。

### 预测范围与误差校准

每个分支都要带上误差范围，误差随车辆运动模型向前传播。需要区分当前状态估计误差、未来输入未知和模型误差，输出随时间变化的位置、速度和航向联合预测。

随机运动学模型提供了均值与不确定性共同传播的参考[5]。FORCE-OPT 则说明，可以保留多个预测区域并校准其尺度，不必将所有分支压成一个大的高斯区域[15]。

范围是否合适，需要用真实发生的结果检查。每次保存预测，等目标时刻到来后再计算误差。离线校准优先按整段未来轨迹设计；逐点覆盖和整段覆盖分别报告。CF-RNN、Safe Planning 和 CAFHT 提供了多步覆盖与轨迹级校准的参考[11、13、18]。

校准和测试数据按独立运行或车辆轨迹分组划分，不能把同一条轨迹中高度重叠的窗口随机拆开后当作独立样本。模型调参、校准和最终测试分开进行。仿真真值可用于离线评价，但不能提前送给在线预测器。

统计声明要对应实际方法和数据条件。独立校准、在线更新、逐点覆盖、整段覆盖和长期平均覆盖是不同问题。CAFHT 的逐步预测结果也不能直接作为本项目一次预测整段未来的证明[11—13、17—18]。

### 预测失效后的处理

持续比较实际观测与先前预测，记录预测漏出范围的频率和幅度。出现明显偏差时，应扩大范围、降低可信时域，或明确输出“不可信”，而不是继续给出过于集中的预测。

自适应共形预测、SODA-MPC 和 FORCE-OPT 为延迟误差更新、失信监测和保守备用提供了参考[12、14—15、17]。具体阈值与恢复规则需通过测试确定，不能承诺检测到所有未知变化。

统计预测集合与物理可达外包分别输出。前者描述校准条件下较可能的未来，后者覆盖声明初态、输入和模型约束下允许的运动。如果只使用有限采样，结果应称为样本预测包络，不能当作确定性全覆盖。未经证明，也不能通过随意裁剪预测范围来保留原来的覆盖声明。

### 从车辆预测到甲板预测

后续着陆使用的是甲板状态。需要根据车身航向、甲板尺寸及安装偏移，将车辆参考点转换为甲板位置、材料点速度和旋转后的边界。转弯时，甲板偏置点的速度包含角速度引起的分量。

输出应保留位置、速度和航向的关联。已有第五阶段的刚体几何与接触计算可供核对，接口在后续接入时另行验证。

## Linux 端的工作

Windows 端负责文献、研究路线、总体设计及结果分析；Linux 端负责具体推导、代码、测试和仿真。GitHub 用于同步版本、必要证据和进度。

本阶段先完成以下工作：

1. 核对可获得的观测和车辆参数，写明运动模型、状态估计、多模型更新及不确定性传播方程。
2. 实现独立预测模块，固定输入输出格式。时间网格、各分支轨迹或集合、权重、就绪状态、观测年龄和可信状态应能保存、回放。
3. 实现预测记录与延迟误差队列，分别完成离线校准和在线失效监测。
4. 设置匀速/匀加速、单转向模型、多模型未校准、校准后模型等对照。先验证预测本身，再讨论着陆决策。
5. 提交源码、依赖、运行命令、配置、测试结果和简要结论。记录实际采用的方法、与本说明的差异及其原因。

车辆场景生成器与预测器分开。先在声明运动范围内进行参数覆盖和边界测试，之后再安排具体情景。不得向预测器传入尚未发生的世界指令或未来真实轨迹。

## 第一阶段看什么结果

评价时同时检查预测误差、覆盖水平、集合大小、物理违规和计算耗时。位置误差可报告 ADE/FDE，范围则分别报告逐点覆盖、整段覆盖以及位置/速度/航向联合覆盖。不同方法在相同观测条件、数据划分和计算预算下比较。

范围画得很大虽然容易覆盖真实运动，但对着陆未必有用。因此需要比较同等覆盖水平下谁的范围更紧，以及运动变化后谁能更快发现失准。

预测模块通过验证后，再设计无人机等待、下降和退出的决策。当前路线借鉴了多项已有工作，具体贡献需由对照结果和进一步文献比较来确定。
