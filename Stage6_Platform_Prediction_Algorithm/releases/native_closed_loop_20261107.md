# 第六阶段：预测算法与四轮平台原生闭环交付

本包包含车辆预测算法、甲板接口、无人机降落联调源码，以及通过核验的 Gazebo / ArduCopter 实际运行证据。构建程序只有在匀速落台、变速落台和声明的预测中断退出三项均通过后才生成交付包。

## 核验结果怎么读

`evidence/native_outcome_summary.json` 区分两次甲板降落与一次故障退出。故障退出通过表示中止下降、返航、正常地面 LAND 和停转；不能计作第三次甲板降落。每次运行均有前台原生窗口、从解除暂停前开始的完整录屏、原始位姿、原生接触事件及飞控日志。指令、飞控、物理接触或退出、预测因果链分别核验。

本包选入同一算法版本在两个运行批次中核验通过的三项证据；匀速项于系统重启后独立复测，不伪装成一轮连续完成。早期失败和系统重启中断记录保留本机，不包含在本包中；不能据此声称所有实际尝试都成功，也不以这三个样本估计总体成功率。本机 `outputs/仿真时间总索引.md` 包含全部第八阶段尝试；本包时间表只对应所选通过批次。

时间均为北京时间。墙上时钟开始、结束及单调时钟实际耗时见 `evidence/时间记录/`；场景时长取原始物理时钟的首末跨度，见各场景 `observed_physics_clock.json`。不补造历史中断的结束时间。

## 实际采用的算法

状态为 `[x,y,psi,v,a,kappa,j,eta]`，满足 `xdot=v*cos(psi)`、`ydot=v*sin(psi)`、`psidot=v*kappa`、`vdot=a`。四种通用机制分别描述近匀速、速度变化、近恒曲率及曲率变化；加速度和曲率按各模式衰减，急动度与曲率变化率具有连续时间记忆。UKF 处理带时间戳的位置和航向，IMM 根据观测似然更新模式权重。

在线输入只有已经收到的位置、航向、时间和协方差。车辆生成器的轴距、方向盘、未来速度命令和路线不进入预测器。参考点偏移采用独立开发数据拟合的值 `(0.6786706955992161,0)` 米；车辆预测映射到甲板中心及材料点速度，包含旋转偏移项。

每次计算四模式各 12 条、共 48 条完整时间相关轨迹，预测两秒、网格 50 毫秒。跟踪名义轨迹选择一个物理分支，挑战分支的后验比超过 1.5 才切换；全部分支仍参与不确定性范围。范围相对当前名义轨迹在相同绝对目标时刻重新计算，不把相反转向平均成直线，也不丢弃失败分支后重新归一化。

本机平缓运动联调对当前状态滤波的纵向急动度过程噪声采用通用值的 0.01，依据开发数据中的加速度估计误差选择；未来轨迹采样保留通用过程噪声的完整 1.0 倍。它改变当前估计假设，不构成更强的覆盖保证。最终原生复测使用预先固定的新位姿噪声种子 20261109；未来采样仍使用原种子规则，未声称所有随机源都更换。位姿观测另加 2 毫米 / 0.002 弧度噪声和 40 毫秒延迟；无人机状态沿用原仿真桥的真值与因果拟合。

飞行进程执行轻量滤波，独立进程产生完整多分支样本。原 120 毫秒观测过期门限、接触、停转和安全退出门限保留。预测失信时取消下降并执行原返航和正常 LAND 流程。四轮模型使用原生轮胎关节及 Ackermann 转向，没有用改位置实现车辆运动。

## 适用范围与差异

原生闭环使用未校准的有限样本包络及观测运动变化带来的工程扩张。它不是确定性物理可达外包，也没有部署概率保证。四至十二秒的规划候选属于条件名义外推，不能称为同样长度的可信预测范围。

独立数值实验已实现整批分组、延迟误差队列、校准诊断和在线失信监测。原校准的约 0.497 米位置扩张对小平台过于保守，本轮没有把它偷偷缩小后称作已校准着陆集合。数值实验与原生闭环分别记录。数值对照中，多模型并不在所有高动态边界上优于单模型，范围紧致性和高动态泛化仍是研究限制。

`numerical_validation/` 保留上述数值实验的原独立源码版本及运行脚本；它使用原通用滤波设置，不能与本轮原生联调参数混为同一实验版本。历史数值实验测试记录另存为 `evidence/historical_numerical_tests.txt`，不混入本轮三组测试计数。运行这些数值脚本属于 Python 数值实验，不能作为 Gazebo 实跑证明。

此前三个前台原生车辆预测批次的 ADE 分别约为 0.027、0.031、0.044 米，两秒末 FDE 约为 0.070、0.075、0.111 米，详见 `evidence/three_native_car_prediction_runs.json`。这些批次只验证车辆预测，不冒充无人机降落。

## 源码与复现

`source/` 来自匀速复测开始时冻结的源码快照。构建时逐文件核对所选三项的全部非 verification 文件哈希一致；运行选择与开发状态记录允许不同，各批次原始哈希清单均保存。`SHA256SUMS.json` 校验交付文件；`evidence/original_source_sha256.json` 对应运行冻结的完整原始快照，其中计划、开发诊断和陈旧状态文件未作为公共交付文件选入。额外提供通用核心及原规划策略回归测试，未修改原第五阶段工程。

Python 3.12 下的本机代码核验：

```bash
cd source
python -m pip install -r requirements-host-tests.txt
python -m unittest discover -s tests_core -v
python -m unittest discover -s tests -v
python -m unittest discover -s tests_legacy -v
```

三组分别为 36、17、15 项。安装依赖和这些测试只验证代码，不能代替下面的原生仿真。核心文件输入输出使用 `python -m stage6 --help`，只依赖 `requirements-core-tested.txt` 中的科学计算库。

原生运行还需要已部署的 Gazebo Harmonic、原生 ArduCopter SITL、供应商模型资源和镜像 `hs-fyp-demo:20261102-verified`；这些大体积依赖未放进源码 ZIP。启动脚本记录了本机实际部署路径及挂载方式，不能把仅安装 Python 依赖描述为完整部署。在本机原工作区运行：

```bash
bash work/stage8_closed_loop/authenticate_foreground.sh
```

系统认证只在桌面终端完成。脚本必须连接当前桌面 `DISPLAY=:0`，确认所属原生窗口、录屏和数据订阅后才解除物理暂停。运行中不关闭已认证终端。需要新复测时，选择文件位于 `work/stage8_closed_loop/verification/native_case_selection.json`；当前批次退出后再触发启动记录目录中的 `closed_loop_retry.request`，不会覆盖旧结果。

完整录屏及体积较大的原始数据保留本机，绝对路径、文件大小和 SHA-256 见 `evidence/raw_artifact_manifest.json`；本包包含核验摘要和从实际录屏提取的结束画面。各场景的核验程序在 `source/tools/`，运行时使用对应原生部署环境。全部配置限定为仿真用途。

## 记录与磁盘留存

本轮全量原生数据仅为限定时长的最终核验采集，不作为日常默认记录模式。后续日常运行应保存摘要、关键事件、降采样数据与复现参数；全量调试数据需限定时长并设置空间预算。已有原始核验证据暂留本机，历史清理需另按用户授权处理，不能直接删除。源码包只收录必要结果，不复制高频原始数据或整个运行目录。
